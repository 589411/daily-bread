# 原文亮點（Lost in Translation）— 品質憲法 RULES.md

> 本檔是整個研經系統的**規格與品質來源**。生成模型（Sonnet/Opus）、審核模型（Fable/Opus）、
> 驗證腳本三方都以本檔為唯一標準。沿用 bible-atlas 的哲學：**品質來自規格，而非模型**。

## 0. 第一性原則

1. **生成便宜，驗證才是產品。** LLM 很會編造「聽起來像真的」的字根與雙關。
   所以每一筆條目必須攜帶**可程式驗證的錨點**（原文字串、經節位置），
   驗證器直接抓原文文本比對，不靠「讀起來通順」。
2. **啟示的載體要說清楚。** 每筆條目必須回答：中文讀者**具體損失了什麼**
   （語音？字根？語義場？文法？結構？）。不允許泛泛的「原文更豐富」。
3. **講解不過度推論。** 區分「文本事實」（可驗證）與「詮釋」（標示為詮釋）。
   範例教訓：耶1:11 的重點是「杏樹的**名字**觸發神的宣告」（語言），
   不是「杏樹早開花象徵神快速行動」（過度讀植物學）。

## 1. 資料源（驗證器使用）

| 用途 | 來源 | 端點 |
|---|---|---|
| 希伯來原文 | WLC（Westminster Leningrad Codex） | `https://bolls.life/get-text/WLC/{bookNo}/{chapter}/` |
| 希臘原文 | TR（公認經文；無重音小寫） | `https://bolls.life/get-text/TR/{bookNo}/{chapter}/` |
| 和合本 | CUV | `https://bolls.life/get-text/CUV/{bookNo}/{chapter}/` |

- bookNo＝正典 1–66，與 `data/bible_books.json` 一致。
- ⚠️ TR 與 NA28 有異文（如約21:15「約拿的兒子」TR＝ιωνα、NA＝Ἰωάννου）。
  `category: "textual"` 或涉及異文的條目，essay 必須註明所依據的文本。
- 希伯來比對：去除母音點與重音符（U+0591–U+05C7），只比子音字串。
- 希臘比對：NFD 分解去 combining marks、轉小寫、尾 ς→σ。

## 2. 分類法（category 只能是以下之一）

| key | 名稱 | 定義 | 例 |
|---|---|---|---|
| `paronomasia` | 諧音雙關 | 兩詞語音相近觸發意義連結 | 耶1:11 שָׁקֵד/שֹׁקֵד |
| `name-etymology` | 名字詞源 | 人名/地名的詞源在敘事中承載意義 | 創2:7 亞當/adamah |
| `semantic-range` | 語義場損失 | 原文一詞的語義場，中文需多詞分擔或無對應 | hesed、hevel、logos |
| `leitwort` | 關鍵字線索 | 同字根在一段/一卷中刻意重複，中譯各處譯法不同而斷線 | שקד 耶1:12→31:28 |
| `grammar` | 文法損失 | 時態/語態/詞序/強調結構無法譯出 | 約21 ἀγαπάω/φιλέω 交替 |
| `wordplay-vision` | 異象雙關 | 先知看見之「物」與神諭之「義」靠語音鉤連 | 摩8:1-2 קיץ/קץ |
| `acrostic` | 離合結構 | 字母詩等形式結構，中譯完全不可見 | 詩119、哀歌 |
| `idiom` | 具象慣用語 | 原文以身體/具象詞表達抽象概念 | 「鼻子長」＝不輕易發怒 |
| `textual` | 一詞多義／異文 | 原文歧義本身是文學手法，中譯被迫二選一 | 約3:8 πνεῦμα 風/靈 |

## 3. Schema（data/insights.json 為條目陣列）

```json
{
  "id": "jer.1.11",                          // 小寫書卷代碼.章.起始節；全檔唯一
  "ref": {
    "bookNo": 24, "book": "耶", "bookFull": "耶利米書",
    "chapter": 1, "verses": [11, 12]         // 涉及的節（整數陣列，升冪）
  },
  "lang": "he",                              // he | el
  "category": "paronomasia",
  "title": "杏樹＝醒著的樹：שקד 的諧音雙關",   // ≤25字，具體，不用「淺談/略論」
  "words": [                                  // 至少 1 個；essay 提到的每個原文詞都必須在此
    {
      "surface": "שָׁקֵד",                    // 帶母音點/重音的完整形
      "match": "שקד",                        // 驗證用：去點後子音串（希臘文＝去重音小寫串）
      "translit": "shāqēd",                  // 學術式音譯
      "strongs": "H8247",                    // H/G+數字；不確定寧可留 null，禁止猜
      "gloss": "杏樹",
      "verse": 11                             // 該詞出現的節；驗證器會抓原文比對 match
    }
  ],
  "loss": "中文「杏樹」與「保守」毫無語音關聯，神回答裡的雙關徹底消失。",  // 一句話，≤60字
  "cuvQuote": "我看見一根杏樹枝。",            // 和合本關鍵句（選填；驗證器去空白後比對 CUV）
  "cuvVerse": 11,                             // cuvQuote 所在節
  "essay": "…（見 §4 寫作規則，markdown，600–1200字）",
  "crossRefs": [                              // 選填；每筆都會被驗證
    { "bookNo": 24, "chapter": 31, "verse": 28, "match": "שקד", "note": "同字根：拆毀與建立都在神的守望下" }
  ],
  "teachingTip": "把 shāqēd / shōqēd 並排念出來讓學員聽。",  // 選填，≤80字
  "confidence": "high",                       // high＝標準辭典共識 | medium＝主流但有異議 | low＝有代表性的少數說
  "meta": { "generator": "opus", "reviewer": "fable-5", "date": "2026-07-05" }
}
```

硬規則：
- `words[].match` 是**驗證錨點**：驗證器抓 `lang` 對應原文該節，正規化後必須以子字串命中。
  希伯來詞常帶前綴（ו/ב/ל/ה/מ/כ），子字串比對已涵蓋；若該形是**停頓形/變形**導致子音不同，
  填實際出現在該節的形。
- essay 中出現的每個希伯來/希臘詞，都必須在 `words[]` 有對應項（審核模型逐一核對）。
- Strong's 不確定就填 `null`。**編造 Strong's 號碼＝整筆退件。**
- 詩篇的 bookFull 用「詩篇」，章稱「篇」。

## 4. essay 寫作規則

1. **結構**（不用標題，用自然段落）：
   a. 原文現象是什麼（把兩個詞並排、講清楚語音/字根關係）
   b. 為什麼中文譯不出來（指名和合本實際怎麼譯）
   c. 這對讀這段經文的方法論意義（文本邏輯，不是靈意發揮）
   d. 貫穿線索（若有 crossRefs，講它如何呼應全卷主題）
2. **語氣**：直接、對讀者說話，可挑戰常見講道的誤讀，但挑戰必須給理由。
3. **信心標示**：植物學/歷史/風俗背景屬「支持性事實」，若非共識要寫「一般認為/有學者認為」。
   詞源學上有爭議的（如民間詞源 vs 語言學詞源）必須明說，`confidence` 對應調降。
4. **禁止**：
   - 引入 `words[]` 沒有的原文詞
   - 「原文的意思其實是…」這種推翻中譯的說法——中譯是「取捨」不是「錯誤」，除非真的是誤譯
   - 編造「這是全舊約唯一一處」這類全稱量化宣稱（除非驗證器能證實）
   - 引用不存在的學者、辭典頁碼
5. 長度 600–1200 字（中文計）。

## 5. 生成流程（sub-agent 模板）

生成模型收到：本檔 §2–§4 ＋ 一筆黃金範例（jer.1.11）＋ 指定的主題清單。
產出：**純 JSON 陣列**，不要 markdown 圍欄以外的說明文字。
每筆生成後自我檢查：match 串是否真的會出現在該節原文？不確定的 Strong's 填 null。

## 6. 驗證層級

- **L1 程式驗證** `tools/validate_insights.py`：schema、分類法、書卷章節合法性、
  原文 match 命中、crossRefs 命中、cuvQuote 命中、id 唯一。必須 `ALL OK`。
- **L2 高階模型審核**（Fable/Opus）逐筆 rubric：
  - R1 語音/字根宣稱正確？（音譯與子音對得上？）
  - R2 詞源宣稱是辭典共識還是民間詞源？confidence 標對了嗎？
  - R3 essay 有無 words[] 之外的原文詞、無錨點宣稱、全稱量化？
  - R4 有無神學過度推論（把詮釋寫成文本事實）？
  - R5 「中譯損失」描述是否對得上和合本實際譯文？
  任一項不過 → 修正或退件，並把錯誤型態記入 HARNESS.md §踩坑。
- **L3 人工抽樣**：使用者抽讀，回饋寫回本檔。

## 7. 已知幻覺型態（審核重點清單，隨踩坑擴充）

1. 編造/錯置 Strong's 號碼（最常見）
2. 音譯與希伯來原字對不上（如把 holem 寫成 qamets）
3. 把民間詞源當語言學詞源（創世記人名詞源多屬**敘事雙關**，不是科學詞源——要寫清楚）
4. 假交叉引用（該字根根本沒出現在引用的節）
5. 全稱量化幻覺（「唯一」「每次都」）
6. 過度植物學/考古學（用背景知識取代文本邏輯）
7. TR/NA 異文混淆（用 NA 的字驗 TR 文本會失敗——match 要用 TR 實際的形）
